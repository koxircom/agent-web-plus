# Agent Web Plus 改名兼容

应用显示品牌已改为 Agent Web Plus，推荐命令为 agent-web；旧命令与数据协议保持兼容。npm 包内部标识暂保留原值，以便构建包原位升级。

## 命令

`agent-web` 与原 `pi-web` 使用同一个启动实现，支持相同的端口、监听地址及 `--no-open` 选项。旧的服务脚本、快捷方式和 `pi-web` 命令继续可用。本次发布保留两个命令。GitHub 仓库已改名为 `koxircom/agent-web-plus`，已有克隆请执行 `git remote set-url origin https://github.com/koxircom/agent-web-plus.git`。旧仓库链接继续通过 GitHub 重定向；不要重新创建同名的 `pi-web-plus` 仓库，以免中断旧链接兼容。

## 数据目录：原位接续

默认目录继续为 `~/.pi/agent`。已有 `PI_CODING_AGENT_DIR` 配置优先保留；不能因品牌或命令变化自动切到空的 `~/.agent-web-plus`。不复制、合并、重建或删除原数据，两个命令始终使用同一份文件。

可使用新的 `AGENT_WEB_DATA_DIR` 指向既有数据目录。若同时配置旧变量与新变量，两者必须指向同一个目录；冲突时拒绝启动，错误中不输出路径或凭据。支持实际指向同一目录的符号链接。只设置新变量意味着用户明确指定该实例的数据位置，不会自动从别处复制数据。

例如原先配置 `PI_CODING_AGENT_DIR=/srv/my-agent`，升级后保持它即可：

```bash
pi-web --no-open
# 或切换到新命令，读取相同目录：
agent-web --no-open
```

目录内容沿用当前实际存储格式：

- `sessions/`：Pi 原会话及分支身份。
- `settings.json`、模型配置、登录信息和扩展状态：原文件继续使用，未知配置字段保留。
- `execution-engines.json`：Codex 执行端连接设置继续使用。
- Codex 的原生历史、队列、目标和置顶仍由原执行环境及配置中的 `historyHome`、`dataDirectory` 管理；不得因 Web 改名重新创建另一套 Codex 配置或复制聊天数据库。

## 浏览器与服务地址

浏览器 localStorage、IndexedDB、Cookie、会话 ID、同步事件名和服务端持久文件名属于兼容协议；其中的 `pi` 前缀继续保留，不能随品牌全局替换。新旧入口的默认端口仍为 30141。

保持同一协议、主机和端口，可继续使用该浏览器原有的草稿、偏好和缓存。更换域名或端口会形成不同浏览器存储来源，不在本次命令改名的自动迁移范围内。服务端历史须继续读取同一数据目录。

旧版增强功能的服务端置顶字段、已有静态置顶清单及浏览器置顶键继续由既有同步路径处理；兼容入口不创建第二份置顶状态。

## 发布时检查

在临时 HOME 中准备旧格式会话、置顶与设置，先用 `pi-web` 启动读取，再停止并用 `agent-web` 读取同一份数据；保留原始文件校验值，验证内容和会话身份不变。另验证自定义旧目录、新别名、变量冲突拒绝及包内双命令。真实用户数据只做只读检查，不执行合并或迁移写入。
