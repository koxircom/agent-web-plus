# Pi Web 主动质量闭环

目标是主动发现、复现、修复和验证缺陷。检查器只收集证据，修复仍由原功能所有者完成；发布沿用既有受控流程。

## 必须保持的结果

| 领域 | 通过条件 | 失败如何处理 |
| --- | --- | --- |
| 发送与保存 | 一个请求 ID 对应一个真实用户条目；确认保存必须经过 fsync | 保留原始待确认消息，不重发不删除 |
| 显示与重放 | 历史/SSE 任意先后、重复事件，同请求只有一个气泡；不同请求同文保留两条 | 用身份合并，退出重复状态写入者 |
| 目录 | summary/full 成员一致；I/O 故障不可变成成功的空列表 | 请求失败，保留上一份有效目录 |
| 搜索 | 媒体体积不隐藏同条文字；提交后内容增长使查询缓存失效 | 保存反例；真实预算触发时明确标记不完整 |
| 历史与缓存 | stale epoch 不覆盖新回合，分页游标和已加载前缀保持 | 拒绝无效响应，按原生读取路径复核 |
| 删除与完整性 | 先写删除计划，再修改文件；完成记录包含实际结果 | 计划写失败阻止删除；结果写失败仍如实报告已删除 |
| 手机/桌面 | 真浏览器验证冷加载、切换、附图和焦点；无控制台异常 | 禁止只凭源码、HTTP200或某个测试数量宣布通过 |

## 三阶段执行

1. **发现**：读取当前安装路径、版本、BUILD_ID、源码及租约，恢复问题台账；运行发现分片和只读完整性检查。收集本轮全部安全分片失败后才编辑，分开产品缺陷、过期测试夹具、环境阻塞与历史未知项。
2. **修复**：先保存会失败的最小反例，再由唯一状态所有者做最小改动；直接影响检查及最小关键 smoke 通过后继续未执行分片。真实数据不用于发送、删除、恢复或模型调用实验。
3. **最终门禁**：稳定候选只做一轮 release 分片、原生构建、完整包浏览器和只读真实入口验收；源码、已安装依赖或命令改变时旧通过证明失效。失败按证据回到受影响分片，不重复全仓库测试。

执行入口（Linux 容器）：

```bash
python3 scripts/qa/run.py --list
python3 scripts/qa/run.py --suite discovery --output-dir ../quality-discovery
python3 scripts/qa/run.py --suite focused --resume --output-dir ../quality-focused
node scripts/qa/release-gate.cjs
```

Windows 可用 `py -3` 替代 `python3`。Node launcher 会找到 Python 3；不安装、下载或升级依赖。执行器最多两个分片进程，记录 source/SDK/Node/命令指纹、分片状态和私有日志。未执行、缺文件、环境阻塞、运行中源码漂移都不能算通过。manifest 是可执行的检查清单；没有列入的功能不得宣称已测试。

## 生产只读探针

`scripts/qa/runtime-probe.cjs` 仅 GET 会话目录和任务状态，通过显式 auth module 从既有受控环境取认证，输出不含凭据/正文的目录元数据。`scripts/qa/integrity.py` 对照 header、发送回执、目录与删除审计；可用有限字节预算验证 native 用户条目。它不会重发、修复或恢复会话。

```bash
node scripts/qa/runtime-probe.cjs --origin http://127.0.0.1:30141 --auth-module /workspace/work/releases/piweb-status-composer-20261006/release-auth.cjs --output ../runtime-catalog.json
python3 scripts/qa/integrity.py --agent-dir /root/.pi/agent --ledger /var/lib/pi-usage/pi-usage-ledger-nas.json --catalog ../runtime-catalog.json --verify-entries --output ../integrity.json
```

已有历史缺口持续留在台账，不因新一次检查未命中、回执过期或某个缓存为空而自动关闭。新出现的未解释“已提交但文件/条目缺失”必须阻断该次发布并报告。已确认的正常 API 删除，与只有计划、无完成记录或完全没有来源证据的缺失分开；共享认证不能证明个人操作者，外部直接 unlink 也不能冒称 API 删除。

## 主动持续执行

每天北京时间 04:10 在当前 Codex 任务恢复最新源码和台账，运行低压力检查。状态和证据不变时保持安静；只对新缺陷、完成的修复、完整性异常或必须人工决定的事项通知。低风险内网修复验收后沿用既有全部任务空闲、无冲突租约、备份/指纹/兼容门禁和一次受控重启。涉及权限、凭据、数据删除/恢复、保留政策或重大架构时保留具体人类决策边界。

本框架不在 Pi 聊天列表新建巡检会话，不调用真实模型做验收。持续任务由 Codex 的当前任务 heartbeat 调度；测试用原生 SDK 的隔离 faux provider，不产生 Pi 模型费用。

## 当前未覆盖边界

- 搜索保留每文件 16MiB 和总 3 秒预算；单行超过该范围、目标在读取边界之外或候选超限，结果仍可能不完整，界面须如实提示。
- 历史文件已消失且缺乏来源审计，无法仅靠 usage 汇总或成功回执还原原始正文。
- 局部组件/真实 React 分片不代替完整包测试。完整包与正式入口仍由发布控制器独立验收。

每一轮实际版本、发现项、复现、修复、指纹与剩余边界记录在对应 release 的 `ACCEPTANCE.md`/JSON 台账；本页定义流程，不硬编码未来运行的通过数。

## 会话故障场景门禁

`tests/session-resilience.pw.mjs` 使用真实 React hook、原生 EventSource 和隔离 HTTP 数据，覆盖手机/桌面 A→B→A 迟到响应、2000 条消息分页与尾部增长、分页迟到时拒绝旧分支并重试，以及空闲/运行中断线重连。重连握手必须使握手前历史读取失效；流快照只包含当前消息，不能代替已保存历史。测试不会向生产发送消息或调用模型。

## 模型切换推理等级

模型能力表是推理等级校正的依据；显式选择和自动默认都不得显示或发送目标模型不支持的等级。Gemini 3.8 Flash 不支持 max 时降为 high，支持的 low/medium 保留。运行中设置只影响下一轮，持久排队模型与等级必须成对匹配，不更改正在运行的请求。核心单测与真实 React 浏览器用例纳入发布门禁。
