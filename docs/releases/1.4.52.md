## 本次核心维护与边界规范

1. **Pi 任务真实控制流与生命周期状态机（Pi Goal Control & Lifecycle Invariants）**
   - **真实控制不经 Prompt**：Pi 引擎的 goal/任务控制流采用原生确定的控制状态通道，不依赖或经由 LLM prompt 文本提示词干预控制逻辑。
   - **暂停先 State 后 Ctx Abort**：执行暂停操作时，状态机优先完成本地状态与检查点持久化更新（先 state），随后才发起上下文取消或执行中止（后 ctx abort），杜绝时序竞态与状态失步。
   - **Idle 冻结挂起等待继续**：处于 idle / 等待状态的任务进入冻结挂起模式，严格等待显式指令继续，绝不自动 resume 恢复执行。
   - **不杀 Detached 后台任务**：进程与会话生命周期治理严格保护 detached（分离模式）的后台独立长任务，会话暂停或取消时不杀灭 detached 后台进程。

2. **图片保存 Native 附件回写与只读下载保护（Image Save & Attachment Routing）**
   - **Native 附件回写不自动下载**：图片编辑与保存优先走原生附件回写机制，直接回写至会话附件与对应存储，不触发浏览器无感或多余的自动 download。
   - **无 Consumer 历史 Readonly 明错显式下载兜底**：在缺少有效 consumer 或处于历史会话只读（readonly）等无法正常回写的场景下，给出明确错误提示，并兜底降级为显式触发下载保护，杜绝编辑成果丢失。

3. **合并未上线 1.4.50/1.4.51 改动与手机 HTTP OS 退出限制（Merged Improvements & Mobile Boundary）**
   - **继承多指与选择器修复**：完整合并 1.4.50 多指污染隔离直至全指离开、跨区域三指防误开侧边栏抽屉，以及 1.4.51 document 级别 `showOpenFilePicker` 旧优先 API 恢复与 Abort 取消防二次回退。
   - **手机 HTTP OS 退出未解决不泛 Claim**：明确移动端在纯 HTTP（非安全上下文）下的系统级退出/返回（OS back/exit 需多次返回等）问题尚未解决，不作过度或宽泛宣称（不泛 claim）；本轮验证基于仿真与协议断言，未解决实体手机 HTTP OS 退出问题。
